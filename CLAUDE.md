# CLAUDE.md - devtools.natanfiuza.dev.br

Leia SEMPRE: docs/SPEC.md, docs/glossario.md, docs/adr/*, docs/design/DESIGN.md.

## Regras

- Stack: PHP 8.3, Laravel 13, Inertia, Vue 3 + TypeScript estrito, Tailwind, shadcn-vue, MySQL, Pest, Vitest.
- Trabalhe por FASE (docs/SPEC.md secao 9). Ao fim de cada fase: rodar `composer test` e `npm run test`, atualizar docs e parar para revisao.
- Nunca fixe nomes de modelo de IA, precos ou limites no codigo: use config/.env/tabelas.
- Nunca registre em log o conteudo de schema ou prompt.
- Toda string visivel via i18n (5 idiomas). Sem texto hardcoded.
- Decisao nova relevante => novo ADR em docs/adr/ e termo novo => docs/glossario.md.
- Tools do cliente rodam 100% no navegador; nada de requisicao ao servidor.
- Deploy: cron executa a copia instalada `deploy/deploy-instaled.sh` (fonte: `deploy/deploy.sh`) a cada minuto. Migrations devem ser retrocompativeis (sem downtime). Guia: `docs/guides/cron.md`.
- GIT: nunca faca commit nem push. O usuario commita e abre PR pelo gitpr, aprovando cada um. Se um commit for necessario, peca intervencao manual do usuario e pare.
- Ao finalizar qualquer tarefa, gerar relatório detalhado em `docs/claude-code/reports/{branch}/{dataatual}_{branch}_{taskname}.md`, onde {dataatual} deve ser substituida pelo data atual, e onde {branch} deve ser substituida pela branch atual, onde {taskname} deve ser uma descricao curta da tarefa, sem espaços ou caracteres especiais, apenas letras minusculas, separados por underscore.
- Toda vez que um plano de implementação for gerado ele deve ser salvo em `docs/claude-code/plans/{branch}/{dataatual}_{branch}_{planname}.md`, onde {dataatual} deve ser substituida pelo data atual, e onde {branch} deve ser substituida pela branch atual, onde {planname} deve ser uma descrição curta do plano, sem espaços ou caracteres especiais, apenas letras minusculas, separados por underscore.

## BadgeForge

- Ferramenta: /tools/badgeforge
- Especificação: docs/SPEC-BADGEFORGE.md
- ADRs: docs/adr/ADR-062-badgeforge a ADR-090-badgeforge
- API: docs/badgeforge/API.md (OpenAPI 3.1.0, contrato 1.9.0 em docs/badgeforge/openapi.yaml, servido em `/openapi/badges.yaml`; semântica em `OPENAPI.md`); documentação pública: `/{locale}/docs/badgeforge`
- Fase atual: F9 — API de gestão completa (entregue)
- Regras: SVG é o formato canônico; PNG (F2) via Imagick com cache em disco; fontes empacotadas via `?font=` (ADR-077); providers em `/api/badges/{provider}/{definition}/{path}` (ADR-080).
- Logos personalizados e presets (F3, ADR-078 e ADR-079): SVG multi-path sanitizado persistido só como `viewBox` + paths normalizados; referência pública `u_<ULID>`; limites em `config/badgeforge.php` (Free: 2 logos; pago: ilimitado; presets: ilimitados); gestão web autenticada em `/dashboard/badgeforge` e `/badgeforge/*`; paths buscados sob demanda (nunca nas props); gerar/prever/snippet continua 100% no navegador.
- Acesso a providers (F4, ADR-068/ADR-080): item público é lido anonimamente na API pública (sem token global em `.env`); PAT é do usuário pagador e só para item privado, cifrado, vinculado ao badge pessoal, e a URL leva apenas o ULID. Cache de provider por URL resolvida, payload projetado (sem descrição/README), condicional, stale-if-error e fallback 200 — nunca 500. `parser_class` é inerte; `client_key`/`extractor_key` resolvem clientes e métricas em código.
- Badges pessoais (F4, ADR-081): `/b/{username}/{ulid}.{svg|png}` stateless, só pago cria, arquivo em `storage/app/data/tools/badgeforge/personal/{username}/{ulid}.{ext}`; `?refresh=1` é ignorado — atualizar é `POST /badgeforge/badges/{id}/refresh` do dono; downgrade serve/copia/exclui mas bloqueia edição.
- Docs públicas do BadgeForge (F4, ADR-082): `/{locale}/docs/badgeforge`, namespace i18n `docs`, tabela gerada do catálogo, SEO/sitemap/rodapé; label/message da imagem são neutros de idioma (exceção documentada).
- Endpoint JSON (F5, ADR-083/ADR-084): `/api/badges/endpoint/{ulid}.{svg|png}` é stateless e anônimo; a URL de origem fica só no servidor (`#[Hidden]`, `dontFlash(['url'])`, chave de cache `sha256`, nunca em props/log/exceção). A imagem nunca vira 500: falha vira STALE ou fallback 200, e `?cacheSeconds=`/`?refresh=1` são ignorados (TTL fixo de 300 s). SSRF é obrigatório: HTTPS/443, sem userinfo/redirect, todos os IPs públicos, conexão pinada por `CURLOPT_RESOLVE` e falha fechada sem curl. O throttle é por dono (Free 300/min, pago 3000/min, anônimo 60/min por IP para ULID inválido/desconhecido). Gestão em `/dashboard/badgeforge`; a URL de origem é imutável (trocar = excluir e cadastrar de novo).
- Providers F6 (ADR-085): nove providers e quinze definições — Codecov e Coveralls (`coverage`, percentual inteiro da branch padrão), Laravel (`v` e `dt` de `stats.json`, uma chamada/entrada de cache), PHP e Python (`v`). Os cinco são públicos (`supports_private=false`). Definições de runtime têm `required_params=[]` e `path_pattern=latest` (path literal validado no parser e no builder); a cobertura é formatada por `ProviderMetricFormatter::coverage()` e shape inválido vira fallback 200. Categorias novas: `coverage` e `runtime`.
- Providers customizados (F7, ADR-087): só pago cria/edita (`custom_providers.limit`, default 10, `null` = ilimitado); `url_template` + `path_params` + métricas declarativas (`label`, **JSON Pointer RFC 6901**, formatter `text|number|percent`), sem código, credencial ou auth na origem. URL pública opaca stateless `/api/badges/custom/{ulid}/{definition}/{path}.{svg|png}` (rota registrada antes do provider genérico; `custom` é slug reservado), fora do catálogo/docs/badge pessoal. Template e slugs são imutáveis (trocar = excluir e recriar) e o conjunto de métricas é fixo na criação; o update só muda nome/label/pointer/formatter e bumpa `metrics_version` (namespace de cache). `example_path` faz probe: shape/URL insegura → 422; rede (timeout/DNS/5xx/429) é tolerada. Serving reusa `EndpointUrlGuard`/`EndpointTargetResolver`/`EndpointHttpClient` e **qualquer** falha vira STALE/fallback 200, nunca 422/500. Origem (`url_template`) é `#[Hidden]`/`dontFlash` e nunca sai em props do dono, builder, docs, CSV, log ou auditoria — exceções explícitas: o dono recebe o `pointer`, o admin vê template/pointer na tela de custom providers, desabilita (URL → 404) mas nunca exclui. Downgrade: serve, editar 403, excluir permitido.
- Analytics (F7, ADR-086 — substitui ADR-063): só imagens com dono (badge pessoal, endpoint e provider custom) gravam, em 200 e 304, uma linha por acesso, síncrono e best-effort (`try/catch`; falha nunca quebra a imagem). `badge_views` polimórfica (`subject_type` = `personal|endpoint|custom`, `subject_id` ULID, `definition` só no custom) + `badge_view_dailies` (dimensões com default `''` e unique). Privacidade: `ip_hash`/`user_agent_hash` = HMAC-SHA256 com `APP_KEY`, UA cru truncado, `referer_domain` só host, país por GeoLite2 **opcional** (`analytics.geoip_path`; sem arquivo → `null`). Free 30d; pago 7/30/90, série, referrers, países, formatos, taxa de cache e CSV sem PII; bruto 90d / diário 400d; admin 7/30/90/400. Agregação `badgeforge:analytics:aggregate` (horária) e poda `badgeforge:analytics:prune` (diária) via `task_schedules` (worker obrigatório). Sem API JSON de analytics na F7 — superfície web + CSV.
- Admin BadgeForge (F7): `/admin/badgeforge/providers` (habilitar/desabilitar provider e definição), `/admin/badgeforge/custom-providers` (dono, métricas, template/pointer visíveis, habilitar/desabilitar, sem delete) e `/admin/badgeforge/analytics?window=7|30|90|400` (só dailies, sem somar únicos entre dias), atrás de `can:access-admin` e com `RecordsAdminActions` (auditoria sem URL de origem).
- API de gestão (F8/F9, ADR-088 e ADR-090): `/api/v1/badgeforge/*` fora do grupo `v1/` do AI; catálogo `providers`/`styles` anônimo com ETag/304; recursos do dono com `badgeforge:read` (todo GET) e `badgeforge:write` (POST/PATCH/DELETE), ortogonais ao `ai:query` (token novo continua só com `ai:query`). Reusa as actions/requests da tela; recurso de outra conta é 404; nunca devolve paths do logo, credencial, URL de origem nem `exportUrl`; `api-read` 120/min e `api-write` 30/min por token (`api.php`). A F9 fechou o painel: PATCH de badge/logo/endpoint, rotação de credencial, refresh (`badgeforge-refresh` 10/min por conta empilhado no `api-write`), CRUD de endpoints (Free cadastra) e de custom providers (POST/PATCH pagos → 403 `forbidden`; DELETE após downgrade) e `GET analytics?window=7|30|90` no shape do `OwnerAnalytics`, janela inválida em 30 e `QueryException` → 503 `badge_unavailable`. Contrato 1.9.0 aditivo; sem estilo novo, i18n nova ou preset na API.
- Hardening (F8, ADR-089): static/provider/`/b/` dividem o cap por IP `badgeforge-images` (default 6000/min, configurável) — endpoint/custom mantêm o limite por dono; todo SVG leva CSP `default-src 'none'; style-src 'unsafe-inline'`; recurso inexistente é 404 `not_found`, `QueryException` em `api/badges/*`/`b/*` é 503 `badge_unavailable` com `Retry-After: 60`/`no-store` (origem continua stale/fallback 200); `/b/` usa o envelope `ApiError` e escapa do fallback Inertia; throttle do management é 429 JSON no GET (export CSV) e toast Inertia em POST/PATCH/DELETE; `/up` checa banco/cache/disco do PNG e responde 503 `down` sem vazar exceção.
