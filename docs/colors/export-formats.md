# Formatos de exportação

## Fase 2 — escala (implementado)
Exporta sempre os **11 tons** da escala, na ordem `50–950`, a partir do nome sanitizado da paleta (padrão `primary`; minúsculas, sem diacríticos, `-` no lugar do resto, até 32 caracteres). A base não é exportada como um tom extra.

Valor por tom:

- alpha `1` → `#rrggbb`;
- alpha `< 1` → `rgba(r, g, b, a)` (até 3 casas, sem zeros à direita) em CSS, SCSS e Tailwind v3; `#rrggbbaa` em JSON, Tailwind v4 e nos formatos de token da F5.

Arquivos gerados (`{name}` = slug):

| Formato | Conteúdo | Arquivo | MIME |
|---|---|---|---|
| CSS | comentário com nome e versão do algoritmo + `:root { --color-{name}-50: …; }` | `{name}.css` | `text/css;charset=utf-8` |
| SCSS | `$color-{name}-50: … !default;` | `{name}.scss` | `text/x-scss;charset=utf-8` |
| JSON | `{ "name", "formatVersion", "algorithmVersion", "base", "clippedTones", "colors": { "50": … } }` indentado | `{name}.json` | `application/json;charset=utf-8` |
| Tailwind v3 | `module.exports = { theme: { extend: { colors: { {name}: { 50: '#…' } } } } }` | `tailwind.{name}.config.js` | `text/javascript;charset=utf-8` |
| Tailwind v4 | `@theme { --color-{name}-50: …; }` | `{name}.tailwind.css` | `text/css;charset=utf-8` |

Todos terminam com uma quebra de linha; o formato é determinístico (mesma escala → mesmos bytes). O download usa o MIME acima.

## Fase 5 — design tokens (implementado)

Exporta as 11 primitivas e, quando o painel recebe os papéis do editor, os 8 papéis × 2 temas. O gerador puro não tem papéis (ADR-126): ali a saída é só primitiva. Sem `roles`, os cinco formatos da F2 continuam byte a byte iguais; o JSON nativo ganhou apenas campos aditivos (`formatVersion`, `clippedTones` e, na Etapa 6, `base` — por isso ele é o formato de ida e volta).

Versão do formato: `COLOR_TOKEN_FORMAT_VERSION = 1`, registrada no DTCG (`$extensions["devtools.colors"]`), no JSON nativo (`formatVersion`) e no cabeçalho de CSS/SCSS/TypeScript. O JSON do Style Dictionary fica limpo — o schema clássico não tem slot de metadados — e a versão aparece no painel.

| Formato | Arquivo | MIME |
|---|---|---|
| W3C DTCG | `{name}.tokens.json` | `application/json;charset=utf-8` |
| Style Dictionary | `{name}.style-dictionary.json` | `application/json;charset=utf-8` |
| TypeScript | `{name}.tokens.ts` | `text/typescript;charset=utf-8` |

### Ida e volta

O JSON nativo, o DTCG e o Style Dictionary podem ser importados de volta pelo
**Importar tokens** (Fase 5, Etapa 6). O teste de ida e volta compara base, os
11 tons e os papéis — não bytes: a escala importada é regravada com a versão
atual do algoritmo, e os formatos não guardam o mesmo conjunto de metadados.
Style Dictionary não tem slot de base e usa o tom 500; o JSON nativo e o DTCG
preservam a base e `clippedTones`. Detalhes da validação em
[import-export.md](./import-export.md#importação-validada-fase-5-etapa-6).

### Nomes

- DTCG/Style Dictionary: `color.{name}.{tom}` e, com papéis, `color.{name}.semantic.{light|dark}.{papel}`.
- CSS/SCSS: primitivas `--color-{name}-{tom}` / `$color-{name}-{tom}`; papéis `--color-{tema}-{papel}` / `$color-{tema}-{papel}` (ex.: `--color-light-primary`, `--color-dark-border`). Não dependem de `prefers-color-scheme` nem de classe `.dark`.
- TypeScript: `{camelCase(name)}Tokens` (slug iniciado por dígito ganha o prefixo `palette`), `as const`.
- Papéis são valores literais, não aliases das primitivas: o usuário pode editar qualquer papel.
- Tailwind v3/v4 continuam só com primitivas; papéis claro/escuro não cabem em `theme.colors`.

### W3C DTCG

```json
{
  "$description": "primary - generated by devtools palette generator (tokens v1, algorithm v1).",
  "$extensions": {
    "devtools.colors": {
      "formatVersion": 1,
      "algorithmVersion": 1,
      "name": "primary",
      "base": "#6366f1",
      "clippedTones": [],
      "gamut": "Gamut: tones computed in OKLCH and mapped to sRGB; no chroma clipping."
    }
  },
  "color": {
    "primary": {
      "50": { "$type": "color", "$value": "#eef2ff" },
      "500": { "$type": "color", "$value": "#6366f1" },
      "semantic": {
        "light": { "primary": { "$type": "color", "$value": "#4f46e5" } },
        "dark": { "primary": { "$type": "color", "$value": "#818cf8" } }
      }
    }
  }
}
```

Cada tom usa `$type: "color"`; o alpha continua em HEX8. `$extensions` usa namespace próprio — Tokens Studio e Figma Variables ignoram o que não conhecem. Fluxo de importação: baixar o JSON e importar pelo plugin **Tokens Studio** no Figma ou pelas **Figma Variables** (import de JSON). Não há integração direta com a API do Figma e não se promete compatibilidade universal com qualquer plugin.


### TypeScript

```ts
/**
 * primary - generated by devtools palette generator.
 * Tokens format v1 - algorithm v1 - base #6366f1.
 * Gamut: tones computed in OKLCH and mapped to sRGB; no chroma clipping.
 */
export const primaryTokens = {
    color: {
        50: '#eef2ff',
        500: '#6366f1',
        semantic: {
            light: { primary: '#4f46e5' },
            dark: { primary: '#818cf8' },
        },
    },
} as const;
```

### Alpha e gamut

- DTCG, Style Dictionary, TypeScript, JSON nativo e Tailwind v4 preservam alpha em `#rrggbbaa`; CSS/SCSS/Tailwind v3 usam `rgba(r, g, b, a)`. Consumidores que não suportam alpha descartam o canal.
- Os tons são calculados em OKLCH e mapeados para sRGB. Quando o croma não cabe no gamut, ele é reduzido preservando L e H (ADR-120); os tons afetados aparecem em `clippedTones` (JSON/DTCG) e na nota de gamut do DTCG/TypeScript.
